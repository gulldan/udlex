# Сжатие словаря «форма → лемма». Поиск в OpenAlex и план сравнения

Срез на 19 ноября 2026 года. Для первого эксперимента предлагаются две независимые замены в `exact.hybrid` — OnPair+ для содержимого записей и сжатый массив их смещений. Для второго — кодирование номера правила восстановления леммы с помощью AutoCSF и learned static functions. Первая пара проверяет, сколько можно сэкономить на байтах уже построенного словаря. Вторая проверяет, какую часть выигрыша объясняет морфологическая регулярность конкретного языка.

## Как собрана выборка

Интервал поиска по полю `publication_date` включал обе границы, **19.11.2023–19.11.2026**. Через OpenAlex Works API выполнены 33 текстовых запроса по заголовкам либо по заголовкам и аннотациям. В запросы вошли статические строковые словари, префиксные деревья, независимо декодируемые строки, perfect hashing, функции над статическим набором ключей, морфологические словари и парадигмы, сжатые смещения и rank/select. По ходу поиска добавлены названия найденных методов. Для расширения выборки проверены цитирующие работы в семи группах и 260 идентификаторов из библиографий семи отобранных работ. Площадку, статус и детали алгоритма сверяли по статье, издателю или программе конференции. Поиск использовал английские термины и один шаг по графу цитирований. ## Что уже можно измерить на нашем словаре

Зафиксированный набор UD 2.19 содержит 172 пакета версии `1.0.0.post1`. В 171 пакете есть длинные записи `exact.hybrid` с ключом длиннее 8 байт UTF-8, всего **13 139 002**. В пилоте OptFSST с правилом «оставить общий префикс, заменить остаток» на эти кодированные записи и таблицы символов пришлось **124 983 899 байт**, на все данные времени выполнения — **274 837 485 байт** против **578 374 683** в поставке. Это измерение размера с проверкой декодирования. Для новых методов предстоят измерения размера, скорости работающего читателя и памяти. [Пилот](pilot.json) · [Формат и расчёт](README.md)

Новый подсчёт считает каждую длинную словоформу один раз. Правило — пара из числа удаляемых байтов и дописываемого суффикса после самого длинного общего байтового префикса. `p_max` — доля наиболее частого правила, `H₀` — энтропия его идентификатора в битах на ключ при кодировании без контекста. Эти величины описывают значения, а размер полного словаря включает также ключи, правила и индекс. [Полные результаты по 171 языку](edit-profile.json) · [Код подсчёта](profile_edits.py)

Все 32-битные смещения длинных записей вместе занимают **58 396 552 байта**, а 16-битные вспомогательные параметры хеширования — **8 759 446 байт**. ## Проверяемые гипотезы

Пороги ниже предлагаются для фиксации до реализации кандидатов. Профиль текущего словаря уже просмотрен, поэтому он служит основанием для выбора гипотез. Словарь статический, и при построении кодека доступны все его ключи и значения. Для настройки параметров и оценки задержки нужны раздельные трассы запросов.

1. **H1. OnPair+ даст ещё 5% на полном наборе поверх OptFSST с правками.** Для каждого языка кодируем один и тот же поток записей в существующем порядке. Сравниваем FSST, OptFSST, OnPair16 и OnPair+ на двух представлениях — буквальные форма и лемма либо форма и правка. Учитываем метаданные, таблицы символов и их восстановление при открытии. Если меняется только поток записей, его суммарный бюджет с таблицами составляет **111 242 024 байта**. Большее число отвергает гипотезу о 5%. Отдельно опубликовать результат для 26 таблиц с исходным потоком правок от 1 МиБ и остальных 145. Малый словарь может терять на служебных данных. [OnPair+ и эталонные настройки, §5.2](https://www.vldb.org/pvldb/vol19/p3635-schmidt.pdf)
2. **H2. Замена только массива смещений даст 5% на том же полном наборе.** При фиксированных байтах OptFSST сравнить исходный `u32`, блочную упаковку с базой в каждом блоке и Elias–Fano. Для последнего сравнить обычную поддержку select и orzo на том же верхнем битовом векторе. Для строго возрастающего входа преобразовать повторяющиеся смещения `a[i]` в `a[i]+i` и вычесть `i` после чтения, используя достаточную разрядность. Проверить все соседние границы, включая пустые слоты. Порог для нового массива вместе со всеми каталогами и выравниванием — **44 654 677 байт** при сохранении прежнего выравнивания остальной части. При изменении выравнивания проверять общую границу **261 095 610 байт**. Время двух чтений границ входит в поиск. Если первым сработает H2, замена кодека становится отдельным вопросом. После обеих абляций измерить сочетание кодека и смещений, поскольку новый кодек меняет распределение смещений. [Elias–Fano](https://jermp.github.io/assets/pdf/notes/elias_fano_notes.pdf) · [orzo](https://doi.org/10.4230/LIPIcs.SEA.2025.23)
3. **H3. Прибыль от сжатия правил зависит от распределения конкретного языка.** За одним и тем же точным индексом сравнить существующий `+rule`, упакованный ID фиксированной ширины, обычную compressed static function (CSF), AutoCSF и learned static function. Для AutoCSF проверяется положительная медианная экономия относительно CSF в группе `p_max ≥ 0,5` и её превышение над группой `p_max < 0,5`. Для learned static function предсказывается больший выигрыш там, где последние символы формы предсказывают правило. Оценить эту предсказуемость по уменьшению кросс-энтропии на отложенных леммах со сглаживанием. Проверить положительную ранговую связь с экономией между языками. Нулевой или обратный эффект противоречит соответствующему предсказанию. Оба опыта включают модель, таблицу правил, исключения и проверку полного ключа. Показать байты слоя значений и полного словаря. [Learned Static Functions](https://doi.org/10.14778/3796195.3796205) · [AutoCSF](https://doi.org/10.1145/3799682.3841067)
4. **H4. Ускорение индекса сохраняется при запросах к отсутствующим словам.** Для C²-Marisa парный контроль — MARISA. Для non-minimal k-perfect hashing — PtrHash с точной проверкой ключа. PHastR сравнить отдельно с `phast` и PtrHash. Всем дать один и тот же слой значений. Для каждой пары заранее обозначить, что будет считаться выигрышем, например верхняя граница 95%-го интервала отношения p95 задержек на промахах ниже 1 при не большем размере полного индекса с ключами. Показать также результаты попаданий и естественной смеси. У ESA наибольшие ускорения получены на отдельных архитектурах при ≥30 млн ключей, тогда как самая большая длинная таблица этого каталога содержит 3,05 млн. [C², §5](https://openproceedings.org/2027/conf/edbt/paper_35.pdf) · [ESA](https://doi.org/10.4230/LIPIcs.ESA.2026.20) · [PHastR](https://arxiv.org/abs/2610.17833)
5. **H5. Шаблоны парадигм окупаются при нескольких словоформах одной леммы.** Сгруппировать тот же закрытый набор пар по лемме, извлечь повторяющиеся шаблоны и закодировать исключения и фактически присутствующие формы. Сравнить с `+rule` при одинаковой полноте словаря. Предсказание — положительная связь экономии в байтах на пару с числом форм на лемму и долей форм, покрытых общими шаблонами. Любая принятая лишняя форма нарушает условие опыта. Показать языки, на которых маски присутствия и исключения обходятся дороже совместного хранения основ. Это предлагаемая адаптация для udlex. [MorfFlex](https://aclanthology.org/2026.lrec-1.899/) · [Principal Parts Detection](https://aclanthology.org/2025.conll-1.17/) · [Исторический контроль MorphoDiTa](https://aclanthology.org/P14-5003/)

## Общие условия сравнения

- **Одинаковый словарь.** Зафиксировать хеш отсортированного потока пар для каждого языка и слоя. Сверить байты каждой леммы и сохранять различие между попаданием с ответом «форма без изменений» и промахом. Для отрицательных запросов использовать естественные отсутствующие формы и проверенные по эталону близкие варианты с заменой, обрезанием или добавлением символа. Схема должна гарантировать точное членство. В хеш-таблице для этого годится сравнение полных байтов. В префиксном дереве — полная форма с признаком конца.
- **Раздельные нагрузки.** Подсчёт размера охватывает все 172 пакета. Для замеров скорости использовать текущую панель Q5 из 14 языков, естественный порядок токенов и только те запросы, которые дошли до соответствующего слоя в рабочем каскаде. Дополнительно измерить равномерные попадания, естественные и близкие промахи, прогретый режим и первый запрос в новом процессе с заданным состоянием страничного кеша. Полностью материализовать байты леммы. Многоисточниковые словари оценить отдельной серией. В данном одноресурсном каталоге лишь один непустой внешний слой, 547 записей. [Панель эксперимента](../encoding/run_final.sh) · [Протокол переноса](../transfer-protocol.md)
- **Статистика и воспроизводимость.** Показать суммарные байты, медиану изменений по языкам, число выигравших языков и байты по компонентам. Отдельно указать размер архива, пиковую память сборки, RSS, время открытия, p50/p95 по попаданиям и промахам и сквозные токены/с. Конфигурации выбирать на development-трассах, затем заморозить на отложенных корпусах. На одном ядре чередовать сравниваемые методы в парных блоках независимых запусков. Строить 95%-е интервалы по блокам. Для итогового выбора предлагается нижняя граница 95%-го интервала не менее 0,95 по сквозной пропускной способности относительно поставляемого udlex.
