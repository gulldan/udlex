# Бенчмарк udlex для OpenSearch 3.10.0

Набор воспроизводит сравнение на 224 языках из сборки словарей от 20 ноября 2026 года. Поставьте Docker с Compose и распакуйте архив на Linux, macOS или Windows с Linux-контейнерами. Образ собирается нативно для x86‑64 и ARM64. Для полного прогона ориентируйтесь на 8 ГиБ памяти и 15–20 ГБ свободного места для Docker. При шести доступных логических CPU четыре получает JVM и два — клиент.

## Запуск с чистой машины

В каталоге с архивом выполните

```sh
tar -xf opensearch-bench-3.10.0-224.tar
cd opensearch-bench-3.10.0-224
docker compose run --build --rm benchmark
```

Эта команда собирает Rust, JNI и Java-плагин из включённых исходников и запускает все пять конфигураций. При первой сборке Docker скачает три публичных базовых образа, зафиксированных по digest. В архиве уже есть зависимости Cargo, официальные плагины для токенизации, словари, тестовая разметка и словари для обеих половин перекрёстной проверки. Этапы сборки и измерения выполняются без сети после получения базовых образов. Порты на хосте не открываются. [Docker Compose](https://docs.docker.com/reference/cli/docker/compose/run/) · [OpenSearch в Docker](https://docs.opensearch.org/latest/install-and-configure/install-opensearch/docker/)

Чтобы сначала проверить установку, выполните `docker compose run --build --rm benchmark smoke`. Короткий прогон проходит все пять конфигураций на русском, японском и кантонском в применимых профилях. Он проверяет обычный тест, обе половины перекрёстной проверки, языковые токенизаторы и реальный поисковый запрос. Для повторного полного замера с уже собранным образом достаточно `docker compose run --rm benchmark`.

## Запуск без интернета

К основному архиву возьмите готовый образ **для архитектуры целевой машины**. После распаковки основного архива выполните в его каталоге

```sh
docker load -i ../opensearch-bench-runtime-3.10.0-linux-amd64.tar.gz
docker compose run --pull never --rm benchmark
```

Для Apple Silicon и Linux ARM64 имя файла — `opensearch-bench-runtime-3.10.0-linux-arm64.tar.gz`. Такой запуск начинает измерения с пустыми индексами и новыми JVM. Для повторной **сборки** без интернета в Docker-кэше дополнительно нужны три базовых образа из [Dockerfile](Dockerfile) для нужной архитектуры.

## Где посмотреть результат

Каждый запуск создаёт новый каталог `results/<время-UTC>-<full|smoke>-<id>/` и печатает его имя. Успешный прогон заканчивается сообщением `Verified … results` и значением `complete` в `run.json`.

| Файл в каталоге запуска | Содержимое |
| --- | --- |
| `summary.json` | Покрытие по профилям, macro pair-F1, медианная скорость, память процесса и результат поисковой проверки |
| `by-language.csv`, `cjk.csv` | F1, входные формы/с, CPU и p95 по языкам и конфигурациям |
| `quality-check.json` | Сверка охвата, числа эталонных пар, pair-F1 и совпадений лемм с ноябрьским эталоном |
| `measurements/<профиль>/` | Фактический набор плагинов, параметры JVM и CPU, результаты по языкам, ответы анализатора и исходные тайминги |
| `run.json`, `cpuinfo.txt`, `logs/` | Версии, архитектура, выделенные CPU, ход выполнения и журнал каждого узла |

Полный и короткий прогоны записываются отдельно. Результаты хранятся на хосте и остаются доступны после удаления контейнера. При сбое начните с `run.json` и журнала соответствующего узла. Повтор команды создаст новый каталог.

## Что измеряется

Основное сравнение включает `standard` на 224 языках, штатный анализатор языка на 37 и `standard → udlex → lowercase` на 224. Ещё две конфигурации измеряют официальные токенизаторы на пяти языках. Каждая конфигурация получает новую JVM OpenSearch 3.10.0 с heap 1 ГиБ. Скрипт выбирает CPU из разрешённого контейнеру набора и проверяет реальные параметры работающего узла.

Качество оценивается по объединению разных словоформ одной леммы. Для 103 языков используется официальный тест, для 109 — два отложенных набора и соответствующие словари. У 12 языков измеряется только скорость. Эталонные пары для среднего F1 есть у 209 языков. Русский интеграционный тест индексирует «Играю с котами» и проверяет запрос «с котом» с подсветкой.

Скорость измеряется локальным HTTP-вызовом `_analyze`. Один клиент отправляет до 256 входных форм, выполняет пять запросов прогрева и три блока не короче 0,5 секунды. Для сравнения скорости запускайте варианты на одинаковом оборудовании и с одинаковыми ресурсами Docker. Память в отчёте — PSS процесса JVM. В [эталонных таблицах](reference/) сохранены показатели первоначального стенда. При повторе сверяются только детерминированные метрики качества и покрытие.

## Перенос и версии

Контрольные суммы входов и ревизии ядра и плагина указаны в [benchmark.lock.json](benchmark.lock.json). Словарные архивы содержат лицензии и атрибуцию. У 39 пакетов суффикс `-nc` указывает на некоммерческие условия.

В метаданных исходной сборки сохранены идентификаторы `0a3334f` для плагина и `4512e56` для стенда. Деревья этих ревизий побайтово совпадают с соответствующими коммитами в репозитории. [Плагин (`ca9df3c`)](https://github.com/gulldan/udlex/tree/ca9df3c1cbd1c026ca66867500844e11d40684e3/integrations/opensearch/plugin) · [Стенд (`18de28b`)](https://github.com/gulldan/udlex/tree/18de28bac217e008cb2b0e5a665c8c427b9281f6/benchmarks/opensearch)

Исходники запуска, методика и эталон хранятся в Git. Каталоги `inputs/` и `build-inputs/` поставляются в одноимённых каталогах архива. Чтобы использовать их с отдельным checkout, скопируйте оба каталога рядом с этим README. Чтобы снова собрать автономный архив из этой папки, выполните `python3 pack.py /путь/к/новому/opensearch-bench-3.10.0-224.tar` с Python 3.11+. Упаковщик сверяет контрольные суммы и создаёт файл `.sha256`. В архив попадает пустой каталог результатов.
